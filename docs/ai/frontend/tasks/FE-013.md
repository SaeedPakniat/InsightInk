## Session capability contract

`CurrentUser` now includes:

```text
capabilities.can_moderate
capabilities.can_administer
```

Frontend uses `can_moderate` only for discoverability/route UX.

Backend `IsModeratorOrAdmin` remains the actual security boundary.

No raw Django authorization flags are consumed by the frontend.

## Navigation and route protection

- Header exposes a shield/Moderation action only when `session.capabilities.can_moderate=true`.
- Small screens keep the moderation action icon-only; wider screens show the localized label.
- New `RequireModerator` route guard:
  - pending -> session loading state
  - session error -> retryable session error
  - anonymous -> /login with return path
  - authenticated ordinary user -> /app
  - moderator/admin capability -> Outlet.
- Protected routes:
  - `/moderation`
  - `/moderation/reports/:reportId`

## Queue

Backend:

```text
GET /api/v1/moderation/reports/
```

- cursor pagination, page size 25, newest first.
- optional status filter.
- frontend default: Open.
- filters:
  - Open
  - Reviewing
  - Resolved
  - Rejected
  - All.
- filter state is URL-driven:
  - default Open keeps clean /moderation URL;
  - other states use ?status=...
- report cards show:
  - report ID
  - localized status
  - localized reason
  - reporter display name
  - target type/id
  - creation time.
- loading/error/empty/end/pagination states included.

## Workflow actions

Existing backend state machine is mirrored exactly.

### Open

Only:

```text
Start review
```

Endpoint:

```text
POST /moderation/reports/:id/start-review/
```

### Reviewing

Possible:

```text
Hide reported comment   (only when target comment is visible)
Resolve report
Reject report
```

Endpoints:

```text
POST /moderation/reports/:id/hide-comment/
POST /moderation/reports/:id/resolve/
POST /moderation/reports/:id/reject/
```

### Resolved / Rejected

- read-only completed case
- no invalid workflow controls rendered.

All actions:

- use shared Django session + CSRF client;
- accept optional trimmed moderator note <= 2000;
- disable controls while mutation is pending;
- invalidate queue + detail after settlement;
- use returned detail immediately when backend returns it;
- hide-comment 204 triggers detail refetch;
- backend field validation is surfaced;
- race/transition failures use localized generic recovery copy instead of leaking backend English into Persian UI.

## Audit trail
