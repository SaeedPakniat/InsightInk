## Creator Studio

Authenticated routes:

```text
/studio
/studio/ideas/new
/studio/ideas/:ideaId/edit
```

Any authenticated Reader can enter Studio and create the optional CreatorProfile.

Creator profile supports bilingual bios.

Avatar upload remains intentionally deferred until a project-wide media upload/storage architecture is accepted.

## Creator Idea lifecycle

Frontend mirrors the final backend lifecycle exactly:

```text
draft
  ├─ edit
  ├─ DELETE permanently
  └─ publish
        ↓
published
  └─ Creator withdraw
        ↓
withdrawn
```

Moderation remains separate:

```text
published
  ↓ Moderator hide
hidden
  ↓ Moderator restore
published
```

Therefore:

- draft = private/editable;
- published = public/read-only for Creator;
- withdrawn = Creator removed from public discovery, history preserved;
- hidden = moderation removed from public discovery.

Studio filters:

- All
- Draft
- Published
- Withdrawn
- Hidden.

Only legal lifecycle controls are rendered.

### Draft deletion

Draft rows expose Edit / Publish / Delete.

Delete requires explicit confirmation and calls:

```text
DELETE /api/v1/me/ideas/:id/
```

Published/withdrawn/hidden Ideas never expose hard-delete controls.

### Publishing

Publication uses only:

```text
POST /api/v1/me/ideas/:id/publish/
```

No status/published_at lifecycle fields are sent through ordinary form payloads.

Publish requires explicit confirmation.

### Withdrawal

Published Ideas expose:

```text
Withdraw from public
```

after explicit confirmation.

Endpoint:

```text
POST /api/v1/me/ideas/:id/withdraw/
```

On success:
- private Studio row becomes Withdrawn;
- cached public Idea detail is removed;
- Feed / Recommendations / Search / Library / public Creator queries are invalidated.

No republish is invented.

## Custom Sources

Creator Studio no longer depends only on system-seeded Sources.

Existing Source selector remains available, plus:

```text
Add custom source
```

Inline Creator Source form supports backend taxonomy:

- book
- article
- paper
- website
- video
- podcast
- movie
- course
- other.

Fields:

- Source type
- Source language
- title
- author/creator/publisher text
- original URL.

Endpoint:

```text
POST /api/v1/me/sources/
```

On HTTP 201:
- Source is appended to the shared Source query cache;
- returned ID is automatically selected in the current draft.

Source creation intentionally remains create-only; frontend does not invent Source editing/deleting.

Search's Source-type filter and public format labels were expanded to all backend-supported types.

## Idea reporting

Public published Idea detail now exposes a quiet:

```text
Report Idea
```

flow using the same locked reasons as comment reporting:

- harassment
- spam
- inappropriate_content
- other.

Endpoint:

```text
POST /api/v1/ideas/:id/report/
```

Anonymous:
- can open report intent;
- receives Sign in to report path preserving current Idea route.

Authenticated:
- reason required;
- optional details <= 2000;
- local success confirmation after 201.

## Direct moderator Idea controls

Moderation-capable sessions see a bounded privileged panel on public Idea detail:

- Published -> Hide Idea
- Hidden -> Restore Idea (when the current mounted moderation context knows the hidden state)

Endpoint pair:

```text
POST /api/v1/moderation/ideas/:id/hide/
POST /api/v1/moderation/ideas/:id/restore/
```

Optional moderator note <= 2000.

Frontend capability controls discoverability only; backend permission remains authoritative.

After hide/restore:
- relevant public discovery caches are invalidated;
- public Idea detail is marked stale without immediately destroying the mounted moderator page, allowing an immediate Restore after Hide.

No hard-delete moderation control is added. Direct moderation uses reversible Hide/Restore and the backend audit trail.

## Idea-target moderation reports

Moderator report detail now understands:

```text
target_idea
```

and displays:

- creator;
- Idea status;
- Source format/title;
- Idea title/body;
- direct Hide/Restore controls.

Comment-report behavior remains unchanged.

Reviewing workflow copy is target-aware:
- comment report mentions hiding a reported comment;
- Idea report directs the moderator to the Idea controls.

Direct Idea audit labels:
- Idea hidden
- Idea restored.

The frontend does not pretend direct audit rows belong to a Report when backend `report=null`.

## Cache correctness

Visibility-changing actions invalidate/remove client state so content does not remain publicly readable merely because React Query recently cached it.

Creator withdrawal removes the cached public Idea detail.

Moderator hide/restore marks public detail stale and invalidates Feed, Recommendations, Search, Creator and Library query families.
