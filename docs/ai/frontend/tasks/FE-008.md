# FE-008 Task Packet — Idea Detail Comments

- TASK ID: FE-008
- GOAL: Add a calm, linear public discussion surface to Idea Detail using the existing comment API.
- BASE COMMIT: `6f491d757cc5d641898c963eb68caeb79b694ba5`.
- API CONTRACT:
  - public `GET /api/v1/ideas/<idea_id>/comments/`
  - authenticated `POST /api/v1/ideas/<idea_id>/comments/` body `{body:string}`, max 4000 trimmed nonblank chars, returns 201 comment
  - authenticated owner-only `DELETE /api/v1/comments/<comment_id>/`, returns 204 and soft-deletes
  - comments returned visible-only, oldest-first, fields `id, author{id,display_name}, body, created_at, updated_at`.
- PRODUCT DECISION: comments live only on Idea Detail; no feed-card comment UI, reactions, reply trees, counts beyond current visible list, or edit behavior.
- PUBLIC UX: anonymous readers can read comments and see a sign-in-to-comment prompt.
- AUTH UX: signed-in readers get a controlled 4000-char textarea and can post.
- OPTIMISTIC CREATE: new comment appears immediately with temporary local ID and Posting state; exact server comment replaces it on success; failure restores previous list and the user's draft.
- OPTIMISTIC DELETE: current user's comment is removed immediately after a two-step Delete -> Confirm delete flow; failure restores it.
- OWNERSHIP: delete control appears only when `comment.author.id === session user.id`.
- DIRECTION: comment body has no backend language code, so frontend infers direction from the first meaningful letter/script; RTL covers Hebrew/Arabic-family Unicode ranges, otherwise LTR. Do not invent a language tag.
- ACCESSIBILITY: semantic discussion heading, textarea label/help, character count, loading live text, error alerts, keyboard-native controls, confirmation/cancel controls.
- VISUAL: restrained marginalia-like list with separators rather than social-media cards; composer is a single quiet panel.
- OUT OF SCOPE: replies, comment editing, likes/reactions, moderation UI, pagination, avatars, comment counts from a separate aggregate API.
- TEST COMMANDS: typecheck, lint, Vitest, build, format check, runtime npm audit.
