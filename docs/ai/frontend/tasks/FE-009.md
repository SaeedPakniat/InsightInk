# FE-009 Task Packet — Saved Library

- TASK ID: FE-009
- GOAL: Give authenticated readers a first-class Saved Library backed by the existing server-side SavedIdea collection.
- BASE COMMIT: `8a904241ef29a4ba58c705058c2e1398c3f04e3d`.
- API CONTRACT:
  - authenticated `GET /api/v1/library/saved/`
  - no pagination
  - returns `[{saved_at, idea}]`
  - only the current user's saved published Ideas
  - newest-saved first via `-saved_at, -id`
  - nested Idea uses the existing safe public Idea representation and active Topics only.
- ROUTE: protected `/library`.
- NAVIGATION: replace the old two-option FeedModeNav abstraction with ReaderNav:
  - For You -> `/app`
  - Latest -> `/explore`
  - Library -> `/library`
- PRESENTATION:
  - preserve backend saved ordering;
  - reuse production IdeaCard;
  - show subtle `saved_at` metadata above each card;
  - bilingual Persian/English UI;
  - multilingual Idea content remains independent of UI language.
- SAVE SYNCHRONIZATION:
  - FE-007's shared per-Idea engagement state remains the button state source;
  - Library screen batch-hydrates engagement states for currently saved Ideas;
  - unsaving from Library removes that Item from the Library cache immediately;
  - failed DELETE restores the Library item and engagement state;
  - successful mutation leaves Library cache stale for future server confirmation/navigation.
- DISCOVERY SEPARATION:
  - content-language preferences filter discovery/recommendations, not historical saved collection;
  - therefore a previously saved Idea remains visible in Library even if its language is no longer selected for discovery.
- STATES: loading skeleton, retryable error, meaningful empty state with link to Latest, success count.
- OUT OF SCOPE: Library search/filter/sort controls, folders/collections, notes/highlights, pagination, offline persistence.
- TEST COMMANDS: typecheck, lint, Vitest, production build, Prettier check, runtime npm audit.
