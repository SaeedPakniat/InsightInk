# FE-010 Task Packet — Search & Discovery

- TASK ID: FE-010
- GOAL: Add a public, shareable Search experience over the existing backend search API without duplicating discovery-language or Idea presentation rules.
- BASE COMMIT: `0100cc8e3d969ac834dfdfd28af985cfecb14f56`.
- API CONTRACT:
  - public `GET /api/v1/search/`
  - cursor-paginated FeedPage shape: `{next, previous, results}`
  - optional query params:
    - `q`: trimmed, max 200 chars
    - `type`: book | article | movie | podcast
    - `topic`: active Topic slug
    - language behavior is handled by existing discovery-language contract.
  - search matches normalized Idea title/body, Source title/original creator, Creator display name and Topic names.
  - ordering is newest matching published Ideas first (`-id`), not relevance scoring.
- LANGUAGE BEHAVIOR:
  - anonymous Search sees all active supported content languages;
  - authenticated Search defaults to the reader's stored content-language preferences;
  - FE-010 does not add a second language picker; authenticated users get a link to existing language settings;
  - explicit language override support remains backend-capable but is not exposed in this UI.
- ROUTE: public `/search`.
- GLOBAL NAVIGATION: Search is a permanent action in the site header, available logged in or out; icon-only on small screens, icon+label on wider screens.
- URL STATE:
  - committed query/filter state lives in the URL, e.g. `/search?q=systems&type=book&topic=philosophy`;
  - typing does not call the backend until form submit;
  - source/topic filter changes update URL immediately;
  - Clear Search removes q/type/topic;
  - browser history/share URLs reproduce the search state.
- SEARCH FORM:
  - semantic `role=search`
  - maxLength 200 input
  - source type select
  - Topic select backed by existing public Topics query
  - Topic filter degrades independently if Topics fail to load.
- RESULTS:
  - reuse production IdeaCard;
  - cursor load-more appends/de-duplicates results;
  - authenticated results batch-hydrate FE-007 viewer engagement state;
  - anonymous results stay readable without private engagement controls.
- STATES: loading skeletons, retryable search error, filtered/query-specific empty states, loaded-result count, end-of-results state.
- RESPONSIVE: single-column mobile form; wider query row and two-filter layout from 42rem; compact header Search icon on mobile.
- OUT OF SCOPE: relevance ranking, highlighting matched substrings, search suggestions/autocomplete, recent searches, explicit language override UI, full-text database search migration.
- TEST COMMANDS: typecheck, lint, Vitest, production build, Prettier check, runtime npm audit.
