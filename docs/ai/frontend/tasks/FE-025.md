## Architecture decision

The repository already defines the PWA implementation order:

1. responsive web app;
2. manifest;
3. icons;
4. service worker;
5. cache static assets;
6. offline fallback;
7. only later design API caching.

FE-025 follows that sequence directly and therefore does not require a Vite PWA plugin or another dependency.

The PWA remains a progressive enhancement. Core web behavior must continue when:

- service workers are unsupported;
- registration is blocked;
- install UI is unavailable;
- the browser does not support desktop/mobile PWA installation.

### Service worker cache boundary

Added:

`frontend/public/service-worker.js`

Cache design is deliberately narrow.

#### Precache

`insightink-precache-v1`

Contains only:

- offline fallback;
- manifest;
- favicon;
- install icons;
- Apple touch icon.

#### Runtime static cache

`insightink-assets-v1`

Only same-origin hashed Vite assets under:

`/assets/`

are runtime-cached.

The runtime cache is capped at 40 entries to avoid indefinite accumulation of obsolete hashed chunks across deployments.

#### Explicitly not cached

The service worker bypasses all:

`/api/`

requests.

Therefore personalized/session/API responses remain network-only and are never stored in CacheStorage by FE-025.

Arbitrary media URLs are also not included in the runtime caching rule.

### Navigation/offline policy

Online navigation remains network-first.

When navigation fails at the network layer, the service worker returns:

`/offline.html`

The fallback is standalone and bilingual:

- Persian primary copy;
- English secondary copy;
- retry button.

FE-025 intentionally does not replay stale authenticated HTML, stale API data, saved-Idea snapshots or account state while offline.

This is the Core MVP offline fallback described by the project documentation, not advanced offline reading.

### Service-worker update semantics

FE-025 does not call `skipWaiting()`.

A newly downloaded worker therefore follows normal browser lifecycle/update behavior instead of forcing a mid-session controller replacement.

Once activated, `clients.claim()` is used so first installation can control the open application promptly.

Old InsightInk cache namespaces are removed during activation while the two current cache names are retained.

## Deployment requirement

Service workers require a secure context in production.

Production deployment must use HTTPS, which is already part of the deployment roadmap.

The service-worker script should be served from the application root. A no-cache/revalidation-friendly response policy for `service-worker.js` is recommended so browser update checks can see new worker versions promptly.

## Explicit exclusions

FE-025 does not implement:

- personalized API caching;
- saved-Library offline snapshots;
- previously loaded Idea persistence;
- offline eBook downloads;
- Background Sync;
- push notifications;
- app-update toast/UI;
- custom install prompt;
- iOS/Android native wrappers.

Those require separate product/data/compatibility decisions.
