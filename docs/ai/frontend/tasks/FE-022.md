## Delivered

### 1. Idea Share

Added a Share action to public Idea Detail beside the existing engagement controls.

Behavior:

- Uses the Web Share API when `navigator.share` is available.
- Shares:
  - Idea title;
  - localized short share text;
  - canonical `/ideas/:id` URL on the current origin.
- If Web Share is unavailable, falls back to copying the canonical Idea URL.
- Clipboard fallback prefers `navigator.clipboard.writeText`.
- A lightweight legacy copy-command fallback remains available when the Clipboard API is absent.
- Native share cancellation (`AbortError`) is treated as neutral dismissal, not an error.
- Success feedback distinguishes:
  - native share completed;
  - link copied.
- Failed sharing/copying presents localized alert feedback.
- No backend endpoint or dependency was added.

### 2. Account preference settings hub

The existing Account page now includes a Reading Preferences card.

It links directly to the already-existing settings flows:

- `/onboarding/interests`
- `/onboarding/languages`

The card explains that these settings shape discovery/recommendations and remains separate from account identity/avatar editing.

The permanent UI-language control remains in the sticky header; it was not moved into Account or a dropdown.

The preference card:

- is bilingual;
- uses semantic navigation;
- is keyboard/focus reachable through normal links;
- uses direction-safe chevron treatment;
- spans the Account grid cleanly on desktop;
- remains single-column and readable on compact screens.

### 3. Route/render recovery boundary

Added a dependency-free React error boundary around the routed content inside `RootLayout`.

The persistent shell remains outside the boundary, so route failures preserve:

- sticky header;
- primary navigation;
- account controls;
- permanent language switch.

The boundary catches unexpected descendant render errors and rejected lazy imports after Suspense resolution.

Localized recovery surface includes:

- clear failure title/body;
- Reload page action;
- Back to home action.

Home target is context-aware:

- authenticated -> `/app`
- anonymous -> `/`

The boundary is keyed by `pathname + search + hash`, so navigating to another route creates a fresh recovery boundary.

### 4. Protected-route return location

`RequireAuth` and `RequireModerator` now preserve the complete protected location:

`pathname + search + hash`

instead of only `pathname`.

`LoginPage` already consumed the stored `state.from`; with the corrected guard state, successful login returns the user to the full route including filters/query/hash.

Example now preserved:

`/moderation?status=in_review#case-12`
