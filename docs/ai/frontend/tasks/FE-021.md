## Product rule

InsightInk has two distinct language concepts:

1. **UI language** — Persian or English interface language, stored as `User.preferred_ui_language`.
2. **Content languages** — the languages a reader wants to discover/read.

FE-021 synchronizes only the **UI language** account preference.

Content-language selection remains unchanged.

## Backend contract consumed

Existing authenticated current-user contract:

`PATCH /api/v1/me/`

Payload used by FE-021:

```json
{
  "preferred_ui_language": "fa" | "en"
}
```

Response remains the complete `CurrentUser`.

The backend `CurrentUserUpdateSerializer` already exposes `preferred_ui_language` as a supported choice field. No backend change or API-contract escalation was required.

## Delivered

### Authenticated account synchronization

- The persistent header LanguageToggle remains in exactly the same header location.
- Anonymous language changes remain local-only through existing `changeUiLanguage()`.
- Authenticated language changes:
  1. apply the existing direction/morph behavior;
  2. PATCH `preferred_ui_language` through the existing account API;
  3. replace `SESSION_QUERY_KEY` with the complete returned user;
  4. invalidate `RECOMMENDATIONS_QUERY_KEY`.

Recommendation invalidation is required because recommendation explanation text is generated by the backend from `preferred_ui_language`.

### Session/account preference precedence

When an authenticated session is available:

- account `preferred_ui_language` wins over a conflicting localStorage value;
- localStorage/document lang/document dir are reconciled to that account value;
- this gives consistent behavior after login and across browsers/devices.

Registration continues to seed the account from the currently selected UI language.

### Failure behavior

Authenticated persistence uses an optimistic interface switch with rollback:

- the language buttons remain busy while persistence is unresolved;
- if PATCH succeeds, the new language stays active;
- if PATCH fails:
  - the previous UI language is restored;
  - localStorage is restored with it;
  - document `lang` and `dir` are restored;
  - a localized `role="alert"` message is shown.

A local persisted-target guard prevents the account-reconciliation effect from racing a just-completed successful PATCH before React Query propagates the updated session object.

### Reduced motion

Existing reduced-motion behavior is preserved:

- no morph overlay when `prefers-reduced-motion: reduce`;
- account persistence still occurs;
- success/failure semantics are identical.

### Header error presentation

- Desktop: localized persistence error remains anchored beneath the header language control.
- Compact <=35rem: error becomes a viewport-anchored strip immediately below the 4.25rem sticky header.
- This prevents clipping when the language control sits near the center/edge of a narrow header.
- The permanent language control remains directly visible and is not moved into any dropdown/menu.

### Registration copy

The previous registration note incorrectly said language changes were only stored on the device.

It now explains that the current interface language is saved to the account at account creation.
