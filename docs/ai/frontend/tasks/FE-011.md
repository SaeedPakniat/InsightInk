## Public creator contract used

- public `GET /api/v1/creators/<id>/`
- public cursor-paginated `GET /api/v1/creators/<id>/ideas/`
- public creator fields:
  - id
  - display_name
  - bio_fa
  - bio_en
  - avatar
  - is_verified
  - follower_count
  - spark_count
  - idea_count
- creator Ideas are published-only and newest-first.

## Viewer follow contract used

- authenticated `GET /api/v1/me/creator-follows/?creator_ids=...`
- response item: `{creator_id, following, can_follow}`
- maximum 100 IDs; duplicates normalized by backend.
- self-profile returns `following=false, can_follow=false`.
- authenticated+CSRF idempotent `PUT /api/v1/creators/<id>/follow/`
- authenticated+CSRF idempotent `DELETE /api/v1/creators/<id>/follow/`

## Frontend implementation

- public route `/creators/:creatorId`
- IdeaCard and Idea Detail creator attributions link to Creator Profile.
- Creator profile contains:
  - avatar/fallback initials
  - verification state
  - UI-language-preferred bio with opposite-language fallback
  - correct lang/dir for fallback bio
  - published Idea / follower / Spark public counts
  - published Ideas via production IdeaCard
  - cursor pagination and de-duplication
  - loading/error/empty/404 states
  - authenticated viewer engagement hydration for creator Idea cards.
- direct Creator Profile intentionally shows all published Ideas from that creator endpoint; it is explicit navigation, not discovery-language ranking.

## Follow UX

- anonymous:
  - `Sign in to follow`
  - login receives return location for the same creator.
- authenticated:
  - viewer state is hydrated from the backend before rendering Follow/Following.
  - `Follow` uses primary treatment.
  - `Following` uses quieter secondary treatment.
  - button uses `aria-pressed`.
- own Creator Profile:
  - no follow mutation control
  - neutral `Your creator profile` state from `can_follow=false`.
- mutation:
  - Follow = explicit PUT
  - Unfollow = explicit DELETE
  - button disabled while mutation pending.
- optimistic behavior:
  - per-creator follow cache updates immediately;
  - public `follower_count` updates +/-1 immediately and never below zero;
  - failed mutation restores previous follow state and previous public Creator object;
  - settled mutation refetches Creator + viewer follow state;
  - recommendations are invalidated without forcing immediate refetch because follow is a recommendation signal.
