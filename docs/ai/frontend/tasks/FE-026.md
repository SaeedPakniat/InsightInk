## Security/browser API audit

No frontend runtime blocker found.

### API transport

The shared API client:

- defaults to same-origin `/api/v1`;
- sends credentials;
- obtains CSRF tokens for unsafe requests;
- supports FormData without manually corrupting multipart boundaries;
- does not store auth tokens/JWTs in browser storage.

### External source links

External Source links using `target="_blank"` also use `rel="noreferrer"`.

### Browser storage

Frontend localStorage use is limited to the UI-language preference.

No password/session/bearer secret is stored there.

### PWA privacy boundary

Service worker never caches `/api/`.

Personalized/session/account data therefore remains outside CacheStorage.

## Non-blocking release caveats

These are evidence/operations caveats, not missing core frontend features.

### 1. WCAG conformance is not certified

The project has:

- semantic component tests;
- keyboard evidence;
- browser accessibility-tree checks;
- visible-focus evidence;
- RTL/LTR review;
- reduced-motion support.

However, the project policy correctly says not to claim WCAG 2.1 AA conformance without comprehensive testing.

**Release wording:** accessibility target implemented with substantial evidence; formal conformance not certified.

### 2. Exact performance NFR thresholds are not benchmark-certified

NFR-01 (<100 ms perceived interaction) and NFR-02 (<300 ms next feed page under defined normal network) have not been turned into formal reproducible benchmark claims.

Optimistic local engagement behavior and bundle discipline are in place, but exact NFR numbers should not be quoted as proven.

### 3. Old-device support is not proven

Current evidence:

- Chromium 157 critical flow;
- Chromium compact viewport;
- Firefox 160 production rendering.

Physical:

- old Android;
- current Android/WebView;
- old iOS/Safari

remain unverified.

The Vite build target is currently:

- `es2018`;
- `safari14`.

Therefore do **not** claim the aspirational iOS 12 / Android 7 evaluation targets as supported.

### 4. Dev-tooling advisory

`npm audit --omit=dev` reports 0 runtime vulnerabilities.

Full `npm audit` currently reports moderate development-tooling findings through:

`typescript-eslint -> @typescript-eslint/typescript-estree -> minimatch 10.2.6`

The advisory is not in the shipped application runtime bundle.

Treat this as dependency-maintenance work, not a core frontend release blocker.

Do not run an automatic major/downgrade-style audit fix during release handoff without a dedicated dependency-upgrade verification task.

### 5. Deployment is still a separate phase

Frontend code is ready for deployment integration, but production hosting must provide:

- HTTPS;
- SPA history/deep-link fallback to `index.html`;
- root-served `/service-worker.js`;
- revalidation/no-cache-friendly service-worker response policy;
- correct manifest/icon content delivery;
- preferred same-origin `/api/v1` routing or deliberately configured `VITE_API_BASE_URL`;
- compatible secure session-cookie + CSRF settings on the backend;
- appropriate media/static hosting.

These are deployment/infrastructure tasks, not missing React features.
