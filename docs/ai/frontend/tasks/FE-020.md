## Backend contract consumed

Public endpoint:

`GET /api/v1/ideas/:idea_id/related/`

Landed backend behavior:

- AllowAny/public.
- Source Idea must be public.
- Candidate Ideas are public only.
- Discovery/content-language filtering is applied server-side.
- Finite related set; no pagination.
- Response item:
  - `idea`
  - `score`
  - `similarity`
  - `reason`
- Related ranking is deterministic from topic overlap plus bounded format/popularity/freshness signals.
- Reason text follows the candidate Idea language.
- Ideas without sufficient shared topics return an empty list.

- Added `RELATED_IDEAS_QUERY_PREFIX`.

- Content-language preference saves now invalidate all related-Idea queries in addition to recommendations/latest feed, preventing stale language-filtered related results.

- Added `RelatedIdeasSection` between source/context and discussion.

- Public/anonymous Idea Detail remains public.
- Authenticated viewers hydrate Spark/Save state for related cards.
- Anonymous viewers do not make engagement-state requests.

### Related section states

- localized heading/body;
- loading skeletons;

- explicit empty state;
- finite related-card list.

### Directionality

- Related reason direction continues to use the existing recommendation reason detection:

- Related Idea body/title direction continues to come from each Idea language.
- Mixed-language cards therefore remain correct inside either English or Persian UI.
