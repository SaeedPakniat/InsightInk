### 3. Authenticated return-path race fixed

The first real Chromium smoke uncovered a frontend race:

- LoginPage correctly navigated to the stored `state.from`;
- at the same time, `AnonymousOnly` saw the newly authenticated session and redirected unconditionally to `/app`;
- in the real app, `/app` won the race.

Result before fix:

`/library?sort=oldest#saved-item -> login -> /app`

Fix:

- `AnonymousOnly` now reads the existing route state;
- authenticated users are redirected to `state.from` when present;
- `/app` remains the fallback when no return location exists.

Regression tests were added for:

- honoring `/library?sort=oldest#saved-item`;
- falling back to `/app` when no return path exists.

This confirms the FE-022 query/hash preservation works in the actual routed application, not only in isolated LoginPage tests.
