## Shared API client

`apiRequest` now distinguishes `FormData` from JSON/string request bodies. FormData requests retain cookies and CSRF but do not receive a manually assigned `Content-Type`, allowing the browser to generate the multipart boundary. Existing JSON requests retain `application/json`.

Focused tests cover both JSON and multipart request behavior.

## Session/cache behavior

`SESSION_QUERY_KEY` remains the canonical current-user cache.

- Profile PATCH replaces the cached user with the complete returned `CurrentUser`.
- Avatar PUT merges only the returned `avatar_url`.
- Avatar DELETE merges `avatar_url: null`.
- Header name/avatar state updates immediately without a page reload.
- Feed/search/library/CreatorProfile caches are not invalidated unnecessarily.

`CurrentUser.avatar_url` now matches the landed backend contract as required `string | null`; legacy fixtures/fallback objects were updated with `avatar_url: null`.
